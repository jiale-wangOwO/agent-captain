# Agent 工作台：0.7 产品与接口契约

## 产品目标

用户面对的是「正在做什么工作」，而不是 SSH 连接、窗口和进程的集合。AgentCaptain 以已登记的工作 agent 为入口，由主控在一个管理会话里负责目标拆解、任务派发、跟进监督、协调和交付审查；机器配置、终端操作和历史查找留作按需使用的能力。用户始终保留最终决策权，也可直接进入任一 worker 的真实终端对话。

首屏回答三个问题：有哪些工作对象、哪些需要处理、怎样继续参与。默认跨机器展示所有已登记、未关闭的真实共享工作终端，临时显示断线的原终端仍保留。旧历史记录可在「全部登记」找回，已关闭记录单独收起；已有浏览器的明确机器、搜索和状态筛选不强制改变，旧「只看允许管理」偏好自动停用。不自动发现机器、不扫描全部 Codex 历史，也不读取每个对象的完整输出。搜索、筛选、命名与置顶帮助减少选择成本，不假造任务完成率或把进程存活当作任务完成。

## 日常操作

- 按工作名称、机器或项目路径找到对象；状态筛选用于关注已连接、需要处理或已关闭的终端。
- 常用对象置顶；卡片直接「命名 / 重命名」，详情页也提供独立命名窗口，断线或列表筛选隐藏时仍能给准确对象命名。保存的是与 MCP 一致的持久显示别名，不改 terminal ID、工作目录、原生 Codex 标题、Session 或进程。
- 命名草稿在轮询和目标切换时保留，取消只丢弃该命名草稿，不清空终端输入。新建终端名称可选，默认使用「机器 · 项目目录末级名称」；现有人工别名不覆盖，机器、路径和短 ID 始终用于区分同名项目。
- 卡片直接打开终端、查看准确关联的会话输出，断线时明确点击重连。
- 当前显示对象与列表筛选分离：改筛选、置顶、后台刷新不能抢焦点、发送草稿或结束工作。
- 链接与浏览器记忆用于恢复显示位置，不代表恢复进程或发送任务。
- 已关闭的记录仍可保留用于核对；「结束终端」继续使用有明确目标的确认窗口，与收起页面不同。
- 卡片「更多」与详情页提供「重开终端…」：这是结束旧终端后换一个新 Shell 的破坏性操作，不是普通重连；必须先核对目标并明确确认。

显示状态描述连接和前台证据：连接在线、前台 agent 可交互、用户正在输入、等待人工处理、显示断开或终端已关闭。状态不能单独证明 agent 开始或完成了业务任务。完整进展来自准确会话记录和交付证据，不从截图尾部重建。

输入状态区分短暂的「你正在输入」与「有未提交输入」。退格、焦点和终端协议报告不会凭空创建草稿；简单文字全部退格删除后可以恢复可交互。真实草稿不会因闲置超时、切换页面或收到输出就释放。历史召回、补全、复杂光标编辑、多行粘贴和 Unicode 编辑无法仅凭按键可靠判断是否已清空时，仍保守保护，等待用户真实提交或取消，不由管理 agent 自动清空。`human_busy` 保持兼容布尔值，`human_input.state` 提供 `typing` / `draft` / `idle` 的非正文状态，接口不包含输入内容。

## 消息时间与机器响应指标

主控发送记录分别显示「创建」和「确认写入」。`time` 是消息记录创建时间；可空的 `submitted_at` 是 Hub 首次收到终端写入确认的本机记录时间，不承诺精确的远端字节写入时刻，更不代表模型已接收、任务已开始或结果已验收。首次确认后保持原值，重试、状态变更或重新加载不重置它。排队、未发送或结果未知不凭推测生成确认时间；旧的已确认记录缺少该值时明确保留未记录，不用创建时间、当前时间或会话输出猜测回填。页面使用浏览器本地时间，`time` 元素保留 UTC，提示中可核对时区。直接键入工作终端不生成该消息卡。

每台 SSH 机器的 `latency` 是已有只读请求的被动观测，不是额外的心跳探测或网络 ping：`metric=ssh_response`，成功时 `last_ms` 包含建连、远端执行、结果传输及原读取策略已经允许的重试，总耗时用单调时钟计算；`last_success_at` 和 `last_attempt_at` 提供墙钟时间。它不是模型响应延时，也不是任务开始或完成的证据。读取缓存状态和绘制指标不会增加 SSH 请求，耗时不会输入 worker。

无成功样本显示 `unknown`；本机显示 `local`，均不伪造 `0 ms`。网页将超过两分钟或时钟发生异常的成功观测标成历史样本。最新请求失败时 `state=failed`，仅用固定 `reason_code` 区分原因；若保留上次成功耗时，必须同时标注它不是当前成功。缓存只属于当前机器与 SSH 目标，服务重启或换路由后重新积累，旧请求迟到的结果不能覆盖更新的观测。延时指标不代替 SSH 显示连接、准确会话读取和前台就绪的独立核验。

## 连接后自动可管理

人和已认证的管理入口使用同一份登记工作列表：所有已登记、未关闭的真实共享工作终端自动可管理，以后连接的终端也自动加入。没有激活开关、逐对象管理授权或新旧插件两份工作名单。临时断线只影响当前连接和输入可用性，不移除原工作对象；已关闭、关闭结果待核对、外部未登记和管理者自身的终端仍不能当成可写工作对象。

Codex 可以对这些登记对象改名、置顶、读取准确输出、按用户意图传达任务和恢复原显示。自动可管理不等于自动启动模型、通过登录、接受审批或覆盖用户草稿。独立管理者保留自己的认证身份、初始化就绪检查、生命周期和送达操作；旧未知结果和已撤销操作不因迁移而重放。不能修改 SSH 目标、接管别人的 tmux、切换供应商或递归管理自身。用户保留最终决策权，登录、信任与审批仍由人处理。

「管理设置」只保留可选的新建工作项目目录：管理者要创建额外工作终端时，必须在该认证身份明确设置的机器与目录及其子目录内执行。这里不是已有工作会话的管理开关；不设置目录也可以管理全部已登记工作。已有主控插件和 Hub 创建的管理者具有相同工作对象成员规则，但新建目录权限仍分别认证和校验。

## 安全重连

### 本机显示服务离线（0.6.1）

网页服务、工作终端显示服务与远端 tmux 是三层独立生命周期。网页在线不代表本机显示服务仍在；显示服务退出也不代表远端 Codex 已结束。

工作台会单独显示本机显示服务状态。点击「恢复显示服务」并明确确认后，只恢复原来绑定的工作服务命名空间；不删除绑定指针、不结束旧进程、不重启模型，也不批量连接其他工作终端或管理会话。旧 PID 必须明确已退出、旧端口必须明确拒绝连接、绑定文件与排他维护锁必须保持一致；状态不明时拒绝替换。

也可在用户自己的终端中执行：

```sh
python scripts/captain.py terminal status
python scripts/captain.py terminal recover --confirm
```

第一条只读，第二条明确恢复显示服务。之后对需要的远程工作点击「重连原终端」。本机已经结束的 PTY 不会被这条恢复命令重新创建。

附着前的 `local_display_unavailable` 是明确未附着的阻塞，恢复服务后可使用原请求键重试。真正的 `unknown` 不会盲目重放：只有旧 owner 的可信 generation、恢复 receipt、当前 owner 和原请求指纹全部吻合，且原显示登记不存在时，用户才能明确核验旧请求。没有可信 owner 身份的旧版 unknown 保留未知结果，不能通过丢失浏览器记忆、换键或恢复服务绕过。

该入口只通过本机网页的 cookie/Origin 校验开放给用户，不能由 MCP bearer 操作全局服务。恢复本身不启动模型、不发送业务输入、不重发 outbox 消息。Windows 后台启动使用独立当前用户进程工厂，并核验实际进程身份，避免随临时启动工具的 Job 一同结束；启动结果不确定时保留原证据，不自动重试。本版未安装系统服务、计划任务或开机自启，也不保证跨关机、休眠和网络故障保持连接；详见[后台服务生命周期](background-service.md)。

「重连」的承诺只有一个：重新显示原来的远程持久终端。

1. 已连接时返回当前状态，不重复附着。
2. SSH 对象先检查准确的原 tmux；附着路径再严格检查，原终端不存在时不创建同名 shell。
3. 恢复后重新核对连接与前台，不能仅凭 SSH 子进程已创建就报告恢复成功。
4. 原终端已关闭、关闭结果不明、本机 PTY 已结束或远程会话缺失时，返回明确下一步；不自动 resume、fork、新建模型或重发任何业务输入。
5. SSH alias 背后的 tunnel 是独立连接层。路由失败时由该工具恢复，Hub 保留原登记与输出，不悄悄重启共享服务。

网页离开和显示断线不会自行结束远端 tmux。远端机器或其 tmux 服务停止则不具备这个保证。

### 明确确认的重开终端

「重连原终端」只附着已有进程；「重开终端…」则保留同一张工作卡片、名称、置顶和目录，换成新的 terminal ID。确认窗口列明机器、工作名称、目录和原终端 ID，提醒保存草稿：身份核验通过后，才关闭仍存在的准确原终端及其前台工作进程，并删除其自有 tmux。独立后台进程不保证结束。原目标、进程身份、所有权或关闭结果不明时保持阻塞/未知，不猜测清理、不接管同名替代对象，也不自动改走普通关闭。

新终端只打开 Shell；工具不发送 `codex` 或 `resume` 命令，不恢复模型、重放任务、草稿或排队输入。但用户自己配置的 Shell 启动文件仍可能运行程序。原会话历史和未决送达证据保留，不再冒充新终端的实时关联；新模型启动后需按其准确身份重新核验/关联。旧网页的输入、尺寸和关闭请求携带打开视图时捕获的 `expected_terminal_id`，服务端拒绝跨代写入。本页保留的未发送按键只供复制，不输入新 Shell，也不持久化到操作记录；刷新前请自行保存。

`POST /api/terminals/reopen` 要求准确 `host`、`thread_id`、`expected_terminal_id`、`confirmed: true` 和稳定 `request_key`。MCP 对应 `reopen_agent`，四个必填参数是 `agent_id`、`expected_terminal_id`、`confirmed: true`、`request_key`；它是破坏性工具，不能从一般任务授权推断出终止工作的确认。独立管理者即使已能管理该 worker，重开仍需该机器与目录的新建权限。已关闭记录、管理者自身或外部会话不能借此重建。

必须检查 `operation_state` 与 `recovery`，不能把 `blocked` / `unknown` 当成功，也不能以连接在线推断模型就绪。未知请求保留原 body/key，网页刷新、切换或重载不自动重发；用户只能同键核对缓存回执，不能换键绕过未知结果。已知阻塞后若要另发一次操作，必须关闭窗口、重新核对并再次确认。成功只证明已换成新 Shell，不证明任务推进或验收完成。

## 网页与 Codex 接口

### 终端滚动与翻页

工作终端和本机管理终端都提供滚轮、PageUp / PageDown（含 Shift）、「上一页」「下一页」「回到最新」。Shift+Home 跳到最早保留的本地历史，Shift+End 回到最新。普通 Home / End 和方向键仍用于真实终端输入。翻页只改变阅读位置，不发送按键、鼠标报告、任务或 resize 请求；用户正在阅读旧输出时，新输出不会主动拉回底部。

SSH 的外层 tmux 可能使用全屏备用缓冲区，使网页 xterm 本身没有历史。此时向上翻页或点击「终端历史」会对当前登记的原 tmux/pane 执行一次只读捕获，并在终端区域显示可滚动、可翻页的文本快照；点击「回到最新」回到持续更新的原终端。进入历史不清空草稿、不新建连接、不改变 tmux 显示、不进入 copy-mode，也不向 Codex 输入。历史视图打开期间，网页暂停该隐藏终端的输入和尺寸调整；远端进程及原显示连接仍在运行。

读取最多 5,000 行、1 MiB 实际保留文本，捕获前后核验同一 session/pane/PID 启动身份及显示状态。快照不是完整的 Codex 对话：tmux 历史上限、清屏或全屏程序重绘可能使旧内容无法恢复。界面明确标注上限与备用屏幕状态，并提供「完整会话输出」跳到精确关联 Session 的真实记录。没有自动抓取其他终端历史，也没有把终端重绘流拼接成伪对话。

只读网页接口为 `GET /api/terminals/history?host=<登记机器>&thread_id=<登记对象>&lines=5000`；仅网页 Cookie 认证，拒绝 MCP bearer、任意 tmux 名称、管理会话引用、已关闭对象和本机的远程捕获。本机仍使用实际 xterm 本地滚动缓冲区。显示断开不自动重连：若原远端终端仍在，可以单独只读查看其保留历史。

| 能力 | 网页 API | MCP 工具 |
| --- | --- | --- |
| 概览 | `GET /api/state`，仅已登记对象的缓存状态 | `list_active_agents`（兼容名），返回全部已登记、未关闭共享工作终端，包括临时断线对象 |
| 改名、置顶 | `POST /api/agents/update` | `update_agent` |
| 恢复原显示 | `POST /api/agents/reconnect` | `reconnect_agent` |
| 确认结束旧终端并重开 Shell | `POST /api/terminals/reopen` | `reopen_agent`（破坏性，需原 terminal ID、明确确认和稳定键） |
| 精确前台与真实记录 | 既有终端/会话输出 API | `get_agent`、`read_agent` |
| 任务和送达核对 | 既有共享输入与送达记录 | `send_agent_message`、`get_delivery` |

`update_agent` 接收准确 `agent_id`，可选 `alias`、`pinned`，以及本次操作的稳定 `request_key`；至少改变一个字段。`reconnect_agent` 只接收准确 `agent_id` 与稳定 `request_key`，不接受任意命令、地址、强制重启或 Session 替换参数。结果不确定时保留同一键并先核对当前状态，不能假设失败后重放输入。

MCP 提供数据、认证与新建目录检查以及受控动作；技能教管理者如何组合它们完成用户目标。插件继续包含 MCP 配置和技能，不为界面管理另启主控模型。参见 [官方插件打包说明](https://developers.openai.com/plugins/build/plugins) 和 [技能与 MCP 的职责](https://developers.openai.com/plugins/concepts/skills)。

已有终端的显示连接与真实会话读取是独立路径。`read_agent` 通过只读 SSH 查询精确关联的 Codex 记录，并在读取前后核验进程与 Session；不会把查询命令输入到工作 agent。新 SSH 失败时保留 `connected` 的真实显示状态，但返回 `output_binding.state=unavailable`、固定的 `reason_code`、空 `messages` 和 `content_complete=false`。`ssh_handshake_failed` 不等于模型停止，`ssh_authentication_failed`、`ssh_host_key_failed`、`ssh_timeout` 等也不混为同一问题。不会回显任意 SSH/provider 错误或凭据，分页失败不会降级把屏幕当正文。恢复后继续使用原 `read_agent` 接口与分页规则，无需重开工作模型或重复派工。

远程读取的绑定、正文读取、后置复核共用一次 SSH 事务；屏幕核验独立进行，不能替代真实会话证据。仅该只读事务可对瞬时传输故障重试一次，不重试认证、主机密钥、协议、身份或游标错误。`include_tools`、`next_cursor` 和 `after_cursor` 的使用规则不变；不同工具模式的游标不能混用。可选 `read_transport` 记录尝试次数与耗时，供区分网络抖动与会话读取问题。

## 更新与验收边界

新字段使用增量迁移，保留原机器、terminal、会话关联、人工别名、独立管理身份和新建目录。旧激活与 worker scope 元数据为兼容保留，但不再限制普通登记工作对象的管理；迁移不重发已有输入、不重置未知操作。网页服务可单独更新；不为部署工作台而结束独立工作终端 broker。兼容旧插件身份升级，避免重复安装两个管理入口。

新的 MCP schema 需要客户端重新加载工具连接。修改源文件、升级插件缓存或重启网页后台不等于已经替换运行中 Codex 对话的工具列表；管理者不应在未核验时声称新工具已加载。现有业务会话和消息不为更新接口而重新发送。

验收覆盖筛选/选择稳定性、命名草稿与元数据持久化、自动工作成员规则、认证身份与新建目录限制、已关闭和缺失终端拒绝、严格附着、幂等恢复、原生会话绑定、剪贴板/滚轮/几何回归。实机检查只核对登记原终端，不把真实业务任务当作测试输入，不关闭仍在运行的 agent。
