# PRON Hub 管理会话：0.5 MVP 实现与产品边界

状态：**管理会话 MVP 已实现，仍为实验性功能**。单元测试和无实机 UI 合同测试覆盖核心状态与权限；真实 Codex 初始化、供应商兼容性、桌面入口和长期恢复仍需要按具体安装版本验证。本文不把源代码完成或深链接打开当作实机验收通过。

产品主线是：**PRON Hub 创建、初始化和恢复一条真实的本机 Codex 管理对话，用户在这条会话交代目标，工作 agent 完成实际工程任务**。用户保留最终决策权，管理者负责收集证据、分发经授权的任务、核对送达、总结结果和待决事项。Hub 不另建模型后端，不默认后台唤醒推理，也不向 worker 注入 CEO 身份或隐藏汇报协议。

## 用户的主流程

首页上方是管理会话卡片，第一次显示「启动管理会话」，已有记录时显示「继续管理」。卡片展示名称、准确的状态/阶段、授权工作会话数量、当前输入入口和错误。准确 Session ID、工作区、终端 ID、工具握手和桌面验证情况放在高级信息中。

第一次只需要：

1. 使用默认名称「我的管理会话」，或自定义名称。
2. 从**已有登记且已激活**的 worker 中明确选择管理范围；零对象也允许启动。不扫描全部机器或历史。
3. 可选地为「创建工作会话」授权已连接机器及具体项目目录，通过目录浏览器选择，不要求记住路径。默认不授权新建工作。
4. 在系统准备角色、工具与原生会话后，在真实管理终端中交流；必要的登录、信任与审批仍由用户完成。

普通流程不要求填写 Python 路径、MCP JSON、模型供应商或 Session ID。机器与工作终端页面仍保留，供配置连接和用户直接参与工作。管理终端使用独立记录、专用工作区和独立终端服务，不加入 worker 列表；打开管理视图、轮询或异步初始化完成不会抢走工作终端中的焦点和输入草稿。

MVP 默认一条管理会话。已有默认记录时，准备操作返回原记录，而不是静默生成第二个 CEO；改范围走独立范围接口。后端可表示不同管理身份，但 UI 不把多管理者创建、共享 worker 或层级管理作为已完成产品。

## 启动、身份与工具初始化

准备阶段在源码仓库外的用户私有状态目录创建工具拥有的管理工作区，写入专用 `AGENTS.md`、项目 `.codex/config.toml`；独立工具连接文件保留在 Hub 私有运行目录。Windows 默认使用 `%LOCALAPPDATA%/PRONHub/management-workspaces`，Linux/macOS 使用 XDG 用户状态目录中的 `pron-hub/management-workspaces`，避免目录信任扩大到整个源码仓库。显式开发/测试 runtime 保持隔离在该命名空间内。不修改业务项目的指导文件，不覆盖用户全局 Codex 配置，不复制认证文件，也不改变用户原有模型、供应商和审批策略。首次目录信任必须由人确认，不能为完成验收而自动批准。

实际启动分两步：

1. 使用本机可信的 Codex 启动入口执行一次 `exec --json` 初始化，显式采用 `read-only` 沙箱和管理工作区。首轮只调用已认证的 `get_controller_context` 自检，然后简短说明范围、等待用户任务；不读 worker 历史、不发任务、不新建 worker、不做业务工作。
2. 从该工具自己启动进程的原生身份事件取得准确 Session ID，保存身份并验证管理工具握手。随后在独立真实终端中用精确 ID `resume` 该对话，并重新提供同一管理者的工具连接。

身份来自受管原生启动事件，不来自模型自报、标题、PID、可见截图或目录中的最新文件。工具握手来自携带独立凭据的 PRON 请求，不来自模型说“已连接”。初始化期间的 worker 操作由服务端状态限制，而不是只靠提示词约定。

「可对话」需要准确身份、工具已核验、以及终端前台可用。仅进程存在或 PTY 连接不够。登录、供应商配置、会话占用、工具失败和后台功能冲突都显示明确错误或「等待你确认」，不自动确认权限、删除锁、fork 或重启共享 daemon。配置尚未可用时，先由用户修复本机 Codex 的日常启动流程。

## 独立授权，不只是提示词中的名单

管理者的身份来自独立 capability，不接受模型传入的 `controller_id` 冒充身份。列举、读取、写入、事件和送达查询都由服务端过滤授权范围；撤权时取消尚未提交的排队写入。MVP 中一个 worker 最多归一个独立范围管理者，未实现多管理者显式共享。

「已激活」是工作对象可以进入管理流程的条件，不等于所有管理者都获得它。新管理者还需要自己的明确 worker grant。「创建工作会话」另行校验机器已连接及 canonical 项目目录范围，创建结果归属该管理者。仅连接了 SSH 不代表获得整台机器创建权限；业务文本不作为 shell 命令执行。

管理者与 worker 分离。服务端拒绝以 worker API 注册、读取、发送或创建管理者，不能管理自己或递归创建下位 CEO。取消激活、撤销授权、终端关闭和用户直接使用仍保留原有语义，不通过迁移重写已有工作终端身份。

这些隔离仅约束 **PRON Hub APIs**，不是 Codex 所有原生工具、其他插件或 SSH 账号的系统权限。保留 Codex 自己的沙箱和人工审批；项目不是多租户网关或整机权限沙箱。

### 旧版已有对话插件的兼容边界

手动安装的旧插件仍可让现有 Codex 对话管理共享激活名单，但其凭据是**全局激活权限**，并没有自动迁移成新管理者独立范围。多个旧主控看到同一全局名单；不能宣传为已隔离。`get_controller_context` 只供新独立范围身份使用。

从 Hub 创建的管理者不需要手动安装该插件：工作区和受管启动已配置工具。保留旧插件不代表它受新授权约束，也不因实现 0.5 而删除用户现有缓存、注销终端或改写供应商认证。

## 状态、幂等与生命周期

| 状态 | 页面含义与行为 |
| --- | --- |
| 尚未创建 | 启动管理会话，默认一个 |
| `prepared` | 初始化包已准备，等待启动 |
| `bootstrapping` / `initializing` | 执行原生初始化、核验准确身份与工具，不派发工作 |
| `attaching` | 恢复准确原 Session 的真实终端 |
| `needs_attention` | 登录、信任、权限、占用或启动提示需用户处理 |
| `ready` | 原生身份、管理工具及终端前台可用，用户可交代目标 |
| `disconnected` | 显示连接不可用，原身份保留，不据此认定任务结束 |
| `desktop_unverified` | Hub 输入已释放，准备同一会话链接；桌面接管未核验 |
| `failed` / `unknown` | 展示明确阶段与错误，核对原操作，不强制新建 |
| `closed` | 管理终端结束、工具身份停用，保存身份与历史用于明确恢复 |

准备、启动和恢复操作保持稳定请求键。浏览器 sessionStorage 保留当前启动操作，后端记录 prepare/start/resume 身份和结果；重复点击、刷新或响应丢失不会靠新键重复生成会话。原结果未知时先核查，不用“恢复”之名新建另一条原生对话，也不自动重新发送初始目标或业务任务。

正常终端按键与持久任务送达不同：UI 不为未知按键结果自动重发。工作任务继续使用已有持久送达查询与稳定 `request_key`；`submitted` 只证明写入，不证明模型接受、执行或验收完成。

收起管理显示、切换工作终端或关闭浏览器，不发送草稿、不关闭管理进程、更不结束 worker。「结束管理会话」经明确确认后，只结束该管理入口、停用其能力；历史和准确 Session 仍保留。关闭 Python UI 服务与关闭独立终端 broker 不是同一动作：broker 或主控机器停止仍可能结束本机 PTY。

## Codex 桌面入口：实验性，不是已验证无缝交接

「在 Codex 中继续」用于打开**同一条已保存原生会话**，不是新建同名对话。MVP 先要求用户明确确认管理者空闲、终端没有未发送草稿，然后核对受管终端状态、释放 Hub 的输入入口，返回 `codex://threads/<exact-session-id>` 供用户点击。

此时记录 `input_owner=desktop`、`state=desktop_unverified`、`desktop_verified=false`。Hub 不再输入管理终端，旧入口中的在途输出响应不会覆盖新所有权状态。这里的“desktop”只是选择了桌面输入入口，**不是证明桌面实际取得会话控制权**。

打开链接不能证明桌面端成功接管、项目信任或 scoped MCP 加载，也不能证明临时 CLI 配置与桌面模型/供应商一致。用户需核对；程序不悄悄同步全局设置或切换模型。持久项目配置和启动覆盖均已准备，但桌面加载规则仍需按安装版本实测。

返回 Hub 前先关闭另一客户端，再点击「继续管理」，使用准确原 ID 恢复，不重新初始化、不重发任务。会话仍被占用时保留明确错误，不 fork、删锁或盲目开第二个写者。

官方 CLI `/app` 路线可以作为后续验证的适配器候选，但 MVP 不自动将它输入终端。只有证明同一 Session、工具身份、输入所有权与失败恢复之后，才能宣称已验证的顺畅交接。[官方 CLI 命令说明](https://learn.chatgpt.com/docs/developer-commands)

## 已实现接口与模块

UI 管理 API 通过已有本机 cookie/Host/Origin 保护，不暴露给 scoped MCP 执行管理者的生命周期操作。

| 接口 | 作用 |
| --- | --- |
| `GET /api/controllers`、`GET /api/controllers/get` | 列举管理记录、核对状态 |
| `POST /api/controllers/prepare`、`start` | 准备角色/工具/范围并启动原生初始化 |
| `POST /api/controllers/resume` | 精确恢复原管理会话，不重新初始化 |
| `POST /api/controllers/scope` | 用户调整 worker 和机器/项目目录 grant |
| `GET /api/controllers/output`、`POST input`、`resize` | 管理终端显示与用户输入，不经过 worker 登记 |
| `POST /api/controllers/desktop` | 明确确认后释放 Hub 入口，返回原 Session 链接 |
| `POST /api/controllers/close` | 明确结束管理入口，不关闭 worker |

管理记录与普通 agent 登记分开，保存准确 Session、专用工作区、终端身份、初始化/操作阶段、独立 scope、工具状态和输入入口。连接凭据在私有 descriptor 中，数据库仅保存能力哈希；不放提示词、深链接、普通响应或命令行参数。终端模块复用已有输入、剪贴板、滚轮、渲染同步和几何竞态保护，隐藏显示不改变几何或发送输入。

## 验收证据与后续工作

本版本实现与测试覆盖：

- 准确原生身份事件、管理工具握手、零范围初始化、错误和未知结果。
- 单默认管理者、稳定准备/启动/恢复键、范围过滤、撤权与递归保护。
- 独立管理终端、无焦点抢夺、worker 草稿保留、滚轮不发送按键、剪贴板与几何保护。
- 桌面链接准确 ID、明确空闲确认、未核验状态、Hub 输入暂停与原会话恢复语义。

**仍需具体环境实机验证**：本机日常 Codex 安装与供应商、真实初始化完成/信任流程、准确原会话恢复、桌面加载同一工具身份和输入所有权、异常中断后的长期恢复。不能从 stub、假 PID 或打开 URL 推断这些验证完成。实机 smoke 使用可丢弃、零 worker grant 的管理者，不以真实业务任务充当初始化验证。

后续优先完成已验证桌面交接；再考虑桌面直接创建、多管理者显式共享、更多任务看板和用户明确授权的自动跟进。不要先重造聊天模型后端，也不默认增加后台推理或定时调度。
