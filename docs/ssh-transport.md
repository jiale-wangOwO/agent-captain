# 外部 SSH 传输接口约定

AgentCaptain 的远端接口是普通 OpenSSH。对于通过 VS Code Remote Tunnel 访问的机器，外部适配工具负责提供可用的 SSH 字节传输；AgentCaptain 不依赖该工具的源码、MCP、实例编号、文件队列或登录状态。

## 配置边界

- 外部工具提供仅监听本机 loopback 的 TCP 入口，或标准 SSH `ProxyCommand` 字节通道。它负责多路连接、全双工、背压、断线清理和自身的启动/恢复。
- OpenSSH 的 host 配置负责目标、用户、公钥和服务器主机身份校验。不能通过跳过主机密钥验证掩盖接入错误；Windows loopback 转发不要求 `ControlMaster`。
- 用户在 AgentCaptain 的机器配置 UI 中填写机器名称及普通 SSH alias。Hub 只保存 `transport: ssh` 与该 alias，不保存 Tunnel 登录令牌或 SSH 私钥。
- 远端使用自己的 SSH 服务、Python 3、tmux。连接机器或打开 shell 不会启动/恢复 Codex，也不选择模型供应商。

## 必须验证的行为

Hub 的常驻显示使用 `ssh -tt`；目录、历史、前台身份与尺寸控制使用独立的短 SSH 连接。因此单次 `ssh host true` 或服务器 banner 成功不足以确认接入可用。

外部适配器至少应支持四个独立并发 SSH 连接。保持一个显示连接时，其他连接必须仍能完成目录、状态和尺寸查询；不能互相消耗输出或阻塞握手。关闭一个连接不能关闭监听器或其他连接。

不同控制操作使用独立的有界预算。前台身份核验允许 20 秒建立 SSH 连接、45 秒完成整个查询，以覆盖高延迟中继上的握手、认证和远端响应；上层显示请求预留 55 秒。发送任务的两轮新身份核验都可能先等待一轮正在进行的显示核验，最多涉及四轮查询，终端请求预留 200 秒，MCP 消息请求预留 225 秒。读取完整会话的 MCP 请求允许 210 秒，原终端连续性重连允许 330 秒；这不改变各次 SSH 查询的上限。尺寸控制和关闭保留各自原有预算。输入还可能等待共享写入队列；超时后仍须核对原送达记录，不能将其当作未送达而重发。

「已连接 · 待核验」表示显示通道仍连接，但最近的前台进程身份尚未核实；它与独立会话历史读取的状态分开。核验失败时会撤销输入就绪状态，后续只能通过新的进程证据恢复，不能依赖旧 ready 缓存或屏幕中出现 Codex 字样。首次连接所需的人工认证仍须由用户处理。

需要验证非交互 Python stdin 脚本、字节完整性、交互 PTY、UTF-8，以及调整尺寸后原 SSH PTY、tmux 客户端、窗口和 pane 的尺寸一致。断开显示连接后，原 tmux 工作进程应保留；仅清理由验证流程创建的临时会话。

调用方也必须正确结束不再使用的输入：无输入的短命令启动后关闭 stdin，或直接调用 OpenSSH 时使用 `-n`。`python3 -` 查询需要先写入完整源码再发送 EOF；常驻 PTY 的 stdin 必须保持开放。不能使用全局 `StdinNull=yes`，否则会破坏目录查询和交互终端。

如果上游窗口重载使传输失效，适配器须明确报错并支持重新选择/恢复新连接。已有工作会话不应通过重复启动模型来“恢复连接”。

## 状态与授权

机器已登记、SSH 可连接、终端已打开、工作 agent 前台可交互是不同状态。已登记、未关闭且绑定原共享终端的工作 agent 自动纳入 Captain 的管理列表，不需要激活开关；临时显示断线保留原登记，但不代表可以发送任务。外部传输不能绕过认证、前台就绪核验、用户草稿保护或工作 agent 的审批；新建终端仍需单独满足机器与项目目录设置。
