# 外部 SSH 传输接口约定

AgentCaptain 的远端接口是普通 OpenSSH。对于通过 VS Code Remote Tunnel 访问的机器，外部适配工具负责提供可用的 SSH 字节传输；AgentCaptain 不依赖该工具的源码、MCP、实例编号、文件队列或登录状态。

## 配置边界

- 外部工具提供仅监听本机 loopback 的 TCP 入口，或标准 SSH `ProxyCommand` 字节通道。它负责多路连接、全双工、背压、断线清理和自身的启动/恢复。
- OpenSSH 的 host 配置负责目标、用户、公钥和服务器主机身份校验。不能通过跳过主机密钥验证掩盖接入错误；Windows loopback 转发不要求 `ControlMaster`。
- 用户在 AgentCaptain 的机器配置 UI 中填写机器名称及普通 SSH alias。Hub 只保存 `transport: ssh` 与该 alias，不保存 Tunnel 登录令牌或 SSH 私钥。
- 远端使用自己的 SSH 服务、Python 3、tmux。连接机器或打开 shell 不会启动/恢复 Codex，也不选择模型供应商。

## 必须验证的行为

Hub 的常驻显示使用 `ssh -tt`；目录、历史、前台身份与尺寸控制使用独立的短 SSH 连接。因此单次 `ssh host true` 或服务器 banner 成功不足以确认接入可用。

外部适配器至少应支持四个独立并发 SSH 连接。保持一个显示连接时，其他连接必须仍能完成目录、状态和尺寸查询；不能互相消耗输出或阻塞握手。关闭一个连接不能关闭监听器或其他连接。

不同控制操作使用独立的有界预算。前台身份核验允许 20 秒建立 SSH 连接、45 秒完成整个查询，以覆盖高延迟中继上的握手、认证和远端响应；上层显示请求预留 55 秒。发送任务的两轮新身份核验都可能先等待一轮正在进行的显示核验，最多涉及四轮查询，终端请求预留 200 秒，MCP 消息请求预留 225 秒。读取完整会话的 MCP 请求允许 210 秒，原终端连续性重连允许 330 秒；这不改变各次 SSH 查询的上限。尺寸控制同样允许 20 秒建连、45 秒完成，上层预留 55 秒；只有收到与原附着和目标尺寸一致的确认才解除尺寸保护。网页合并连续尺寸变化，每个终端仅保留一个在途请求和最后一个待处理尺寸，避免拖动窗口积压控制命令。关闭仍保留原有预算。输入还可能等待共享写入队列；超时后仍须核对原送达记录，不能将其当作未送达而重发。

远程 `read_agent` 将会话绑定、原始记录读取和读取后的身份复核放在同一个只读 SSH 事务中，不再为这三步分别握手；屏幕的前台核验仍是独立证据。该事务的源码和返回正文均压缩传输，返回值按最多 4 MiB 严格解压核验，不改变消息内容、分页或私有推理过滤。大正文的第一次只读事务允许 75 秒完成；仅超时、握手或传输故障可再试一次，重试上限 45 秒，总共 120 秒，连同最多 55 秒的屏幕核验仍低于 MCP 的 210 秒预算。每次重试都重新执行身份核验并沿用同一分页游标。其他短历史查询保持 45 秒；认证、主机密钥、协议、会话身份和游标错误不自动重试，不把此策略用于发送输入、附着或恢复。`read_transport` 只报告尝试次数、总耗时、响应传输字节数和批量核验方式，不返回原始 SSH 诊断。它减少高延迟路由上的握手次数和数据量，不承诺修复外部网络；读取失败时依旧不能把屏幕尾部当完整报告。

「已连接 · 待核验」表示显示通道仍连接，但最近的前台进程身份尚未核实；它与独立会话历史读取的状态分开。核验失败时会撤销输入就绪状态，后续只能通过新的进程证据恢复，不能依赖旧 ready 缓存或屏幕中出现 Codex 字样。首次连接所需的人工认证仍须由用户处理。

同一 Hub 进程中，相同 SSH `target` 的完整会话读取最多一个在途，保护覆盖屏幕核验和语义读取，而不只是最后的正文查询。冲突请求立即返回 HTTP 409 / `ssh_read_in_progress`，不排队、不新开 SSH、不自动重试，也不改保存的会话绑定或原游标；等待前次读取结束后，再手动沿用同一模式的原游标读取。不同 SSH target 和本机读取不互相阻塞。这不是整条路由的独占锁：网页的被动终端核验、尺寸控制和外部 SSH 仍可能并发，Hub 也无法证明两次并发读取就是线路故障的原因。

`read_transport.attempt_trace` 给出各次尝试的固定结果码和耗时。`ssh_handshake_failed` 表示 SSH 报告 banner/kex 阶段失败，不等于游标损坏或 worker 退出；传输故障后原游标未被判为失效，可以处理连接问题后再用。只有原始读取器实际判定文件被替换、截断、改写或游标/工具模式不符时，才按相应语义错误重新获取记录。成功读到一页不能证明中继长期稳定；持续握手失败应修复 SSH 路由，而不是重启 Codex 或重发业务任务。

若原重连已经附着，但后置核验超时，网页会保留原请求的未知结果。对符合严格条件的现有显示，可使用「核对原连接」：只读核对原请求、原本机 owner、SSH 显示进程及冻结的远端 tmux/pane 身份，成功后记录核验结果，不再次附着、不启动模型、不发送输入。尺寸同步仍需独立的成功确认；核对重连本身不会解除尺寸或前台身份保护。

需要验证非交互 Python stdin 脚本、字节完整性、交互 PTY、UTF-8，以及调整尺寸后原 SSH PTY、tmux 客户端、窗口和 pane 的尺寸一致。断开显示连接后，原 tmux 工作进程应保留；仅清理由验证流程创建的临时会话。

调用方也必须正确结束不再使用的输入：无输入的短命令启动后关闭 stdin，或直接调用 OpenSSH 时使用 `-n`。`python3 -` 查询需要先写入完整源码再发送 EOF；只读会话查询、原 pane 核验和终端历史使用压缩源码 bootstrap 减少传输量，保留原命令参数及输出协议，不在远端安装文件，也不延长各次查询预算。常驻 PTY 的 stdin 必须保持开放。不能使用全局 `StdinNull=yes`，否则会破坏目录查询和交互终端。

如果上游窗口重载使传输失效，适配器须明确报错并支持重新选择/恢复新连接。已有工作会话不应通过重复启动模型来“恢复连接”。

## 状态与授权

机器已登记、SSH 可连接、终端已打开、工作 agent 前台可交互是不同状态。已登记、未关闭且绑定原共享终端的工作 agent 自动纳入 Captain 的管理列表，不需要激活开关；临时显示断线保留原登记，但不代表可以发送任务。外部传输不能绕过认证、前台就绪核验、用户草稿保护或工作 agent 的审批；新建终端仍需单独满足机器与项目目录设置。
